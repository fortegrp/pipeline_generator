# Performance Metric Model

The dashboards use four user-facing dimensions:

- `testRunID`: unique execution identifier generated by Jenkins.
- `project`: project selected for the run.
- `scenario`: workload type such as `smoke`, `load`, `soak`, or `stress`.
- `transaction`: request, sampler, or business transaction name.

The `tool` tag is retained as a technical dimension so Grafana can distinguish tool-specific measurements. It is not part of the primary run identity.

## Measurements

JMeter, Locust, and Gatling write request samples to `performance_http_request`:

```text
performance_http_request,project=forte,testRunID=forte_smoke_20260723T120000Z,tool=jmeter,scenario=smoke,transaction=TX_Home response_time_ms=125i,status_code=200i,failed=false
```

k6 writes its native measurements through `xk6-output-influxdb`, including:

- `http_req_duration`
- `http_req_failed`
- `http_reqs`
- `vus`
- `iterations`

The provisioned dashboards normalize `performance_http_request` and native k6 measurements at query time. This keeps continuous k6 streaming intact while presenting the same filters and charts for every supported tool.

## Naming Rules

- Keep `project` stable across repositories and runs.
- Use one of the standard scenario names where possible: `smoke`, `load`, `soak`, `stress`.
- Use stable transaction names such as `TX_Home` or `POST_/orders`.
- Never reuse a `testRunID` for a different execution.
